# OpenRouter API parity: fields and data

Written 2026-11-26. What OpenRouter exposes through its API, field by field, against what Lemru has today, so the team knows what to build. The goal is the same capabilities, not OpenRouter's look or brand.

- **OpenRouter source:** the four skills in `.agents/skills/` (`openrouter-models`, `openrouter-generations`, `openrouter-analytics-schema`, `openrouter-oauth`): SKILL.md, README.md and `scripts/*.ts`. Anything else is marked _(not in the skills; confirm from screenshots or docs)_.
- **Lemru source:** the code on this branch; every claim cites a path.
- **Feature-level comparison** (money, privacy, routing, presets, workspaces): `../openrouter-comparison.md`. This file does not repeat it; it covers API fields and recorded data.

Where our data lives, in short:

| Store                                                                   | Kept                                         | Holds per request attempt                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ----------------------------------------------------------------------- | -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Ledger `credit_ledger_entry` (`kind = usage`)                           | For good                                     | amount charged (micro-USD), `reference` = request id, `virtual_key_id`, `metadata`: `provider_cost_usd`, `markup_bps`, `held`, `provider`, `model`, `request_type`, `fallback_index`, `attempt`, `failed`, `provider_key_id`, `prompt_tokens`, `completion_tokens`, `total_tokens` (`apps/gateway/plugins/credits/plugin.go` PostLLMHook). Only attempts that cost more than 0 are written (`settleSQL`, `store.go`).                                   |
| Gateway log `logs` (`apps/gateway/framework/logstore/tables.go`, `Log`) | 90 days (`apps/gateway/compose/config.json`) | provider, model, served model, status, stop reason, stream, latency, upstream latency, overhead latency, tokens (incl. `cached_read_tokens`, `token_usage` JSON with reasoning tokens), cost and its breakdown, retries, fallback index, selected provider key, virtual key, customer, session id, user agent, app (from user agent), client IP, service tier. No prompts or completions (`disable_content_logging: true`, ADR 0014, commit `c63aea5`). |

## 1. Summary

| Area                                   | Status  | One line                                                                                                                                       |
| -------------------------------------- | ------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| Models catalog                         | Partial | `GET /api/v1/models` has id, name, context, modalities, prompt/completion/cache prices; no supported parameters, dates, description, filters.  |
| Model endpoints / provider performance | Missing | No `/models/{id}/endpoints`; latency, throughput and success counts are in the gateway log, unused for customers.                              |
| Generation record                      | Partial | `GET /api/v1/generation` has 12 of OpenRouter's ~30 fields; several more are recorded but not returned. Content is intentionally never stored. |
| Analytics metrics                      | Partial | Spend, requests, prompt and completion tokens. No performance, cache or cost-breakdown metrics.                                                |
| Analytics dimensions                   | Partial | Day, model (+provider), key, single request. Provider, finish reason, session, streamed, data region recorded but not grouped.                 |
| Credits and top-up                     | Have    | `GET /api/v1/credits`, ledger, Stripe top-up with quote, low-balance alert.                                                                    |
| Keys                                   | Partial | Dashboard keys with limits, reset, expiry; `GET /api/v1/key`. No management keys, no `/api/v1/keys`.                                           |
| OAuth / sign-in for apps (PKCE)        | Missing | Nothing; our Better Auth social sign-in is for our own dashboard only.                                                                         |
| BYOK                                   | Missing | No customer provider keys; every `is_byok` field would be `false`.                                                                             |

## 2. Models catalog

OpenRouter: `GET /api/v1/models` returns `{ data: Model[] }`, public, filters `?category=` and `?supported_parameters=`. Ours: `GET /api/v1/models` in `packages/api/src/modules/v1/models.ts` (`PublicModel`), public, cached 60 s; with a key, filtered to what the organization's data policy can reach. Read by `/models` and `/models/[...id]` (`apps/web/src/modules/marketing/models/catalog.ts`), which filter by text and provider only.

| OpenRouter field                                      | Ours                           | Notes                                                                                                                                                                                    |

| `description`                                         | Missing                        | Gateway `Description` / `additional_attributes`; `additional_attributes` is in `/api/models/details`, unused.                                                                            |
| `created`                                             | Missing                        | Gateway `Created`; not exposed. Needed for "newest" sort.                                                                                                                                |
| `context_length`                                      | `context_length`               | Have.                                                                                                                                                                                    |

### `GET /api/v1/generation/content`

OpenRouter returns `data.input.{prompt, messages}` and `data.output.{completion, reasoning}`, empty under ZDR. **We do not have it and will not**: the gateway stores no prompts or completions (`disable_content_logging: true` and per-request override ignored, `apps/gateway/compose/config.json`; ADR 0014; commit `c63aea5`). If built, the route should exist and always answer with null content, as OpenRouter does for ZDR, so clients written for OpenRouter do not break.

## 4. Analytics

OpenRouter: `GET /api/v1/analytics/meta` lists metrics, dimensions, operators and granularities; queries take up to 2 dimensions, 20 filters, granularity minute to month, 367 days for volume/cost and 31 days for performance and per-request dimensions; management key required. The query endpoint's request shape is in the `openrouter-analytics-query` skill, which we do not have.

Ours: `GET /api/activity/:organizationId?days=1..365` (session auth, `billing:read`) returns totals, by day, by model+provider and by key, from the ledger (`packages/api/src/modules/activity/queries.ts`); `GET /api/activity/:organizationId/requests` lists charged attempts newest first (`generations.ts`); UI in `apps/web/src/modules/activity/`. Day granularity only, no filters, no public analytics API, no CSV _(OpenRouter CSV export: not in the skills; confirm from screenshots)_.

The gateway already computes most of the rest over its log: `/api/logs/stats`, `/api/logs/histogram`, `/histogram/{tokens,cost,models,latency,throughput}`, `…/by-provider`, `…/by-dimension` (`transports/bifrost-http/handlers/logging.go`), filterable by customer. Its window is our 90-day retention, longer than OpenRouter's 31-day cap on these metrics.

## 6. Lemru-only advantages

- **Data policy enforced per organization** (ADR 0015): allowed regions (`sa`, `eu`, `us`, `other`), allowed providers, zero retention, no training; pushed to the gateway as key allowlists (`packages/db/src/schema/providers.ts`, `organization_data_policy`). OpenRouter's skills show ZDR and a `data_region` dimension, not an organization-wide allowlist.
- **Evidence per request, as of that moment**: `data_policy` on every generation, with the policy version and `terms_changed_since` (`packages/api/src/modules/data-policy/evidence.ts`), from append-only history tables.
- **Catalog filtered by policy**: `/api/v1/models` with a key lists only what the policy allows.
- **No content stored, ever** (ADR 0014), not just under ZDR.
- **Per-key limits enforced before the call**: the worst-case cost is held up front (ADR 0009, 0013).
